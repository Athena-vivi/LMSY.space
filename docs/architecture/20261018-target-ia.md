# LMSY.space 目标信息架构与迁移方案

> 状态：**已实施**（2026-10-18）。第 M0–M4 阶段已落地，执行记录见 `20261018-migration-log.md`。
> 尚未完成的只有线上回归验证（本机出网受限），以及人工策展类的数据补齐。
> 前置阅读：`20261018-ia-audit.md`、`20261018-content-model.md`、`20261018-field-dictionary.md`、`20261018-category-spec.md`。

## 1. 职责分层

一句话：**首页负责发现，导航负责完整浏览，搜索负责精确定位，详情页负责完整呈现。**

| 层 | 回答的问题 | 数据来源 |
|---|---|---|
| 首页 | 这里有什么值得看 | 分类计数 + 精选项目 + 年份 + 人物 |
| 导航 | 我要完整看某一类 | 全量索引 |
| 搜索 | 我已经知道名字 | 项目 + 图片 + 人物 + 别名 |
| 详情 | 这个项目到底有什么 | 项目 1 行 + 图片 N 行 |

## 2. 导航（7 → 4 + 搜索）

| 位置 | 入口 | 目标 | 解决的问题 |
|---|---|---|---|
| 1 | **Projects** | `/projects` | 找某一期杂志、某场活动、某个主题 |
| 2 | **Timeline** | `/timeline` | 看某一年发生了什么 |
| 3 | **People** | `/people` | 看某个人及其实物 |
| 4 | **Gallery** | `/gallery` | 只想看图，不知道属于哪个项目 |
| 中 | **Search** | 全局 `Cmd/Ctrl+K` | 已知名称/人物/作品/年份 |

移出主导航（路由保留，不删除）：

| 入口 | 处置 | 理由 |
|---|---|---|
| Exhibitions | 并入 Projects 的分类筛选 | 与 Projects 是同一批数据的另一套皮 |
| Editorial | 改为 Projects 的分类视图 | `category='editorial'` 的子集 |
| Chronicle | 301 → `/timeline` | 改名，语义更直白 |
| Resonance | 移出导航，保留 Coming Soon 路由 | 0 内容，占导航位无收益 |
| Schedule | 移出导航（无入口、无表、硬编码空数组） | 孤儿路由 |
| Duality | 保留为外链组（不占主导航位） | 是社媒聚合，不是站内内容 |

## 3. 首页五区块

| 区块 | 内容 | 数据要求 |
|---|---|---|
| 1. Hero | 档案馆主视觉 + 一句话定位 | 静态 + `site_content_blocks` |
| 2. Explore by Type | 固定入口卡（数量待 D1 定），封面取该分类最新公开项目 | `projects where category=? and portal_visible`，0 结果时用渐变底 + "收录中" |
| 3. Featured Projects | 6–8 张项目卡：名称、类型、人物/作品、日期、封面 | `homepage_featured` 优先，不足时按 `portal_priority + event_date` 补 |
| 4. Timeline Preview | 3–5 个年份节点 → `/timeline/{year}` | 年份由 `event_date` 派生，不用 `created_at` |
| 5. People & Archive Story | 2 张人物卡 + 档案说明 | `profiles`（补头像）+ `site_content_blocks` |

首页所有卡片必须来自真实数据，不得硬编码项目 ID 或标题。

## 5. 搜索与筛选

| 维度 | 来源 | 现状 | 目标 |
|---|---|---|---|
| 项目名 | `projects.title` + `title_i18n` | 已支持 | 增加 `search_aliases` |
| 人物 | `profiles.name/nickname` | 部分 | 姓名 + 别名 + 组合名 LMSY |
| 作品 | 当前只能匹配标题文本 | 无实体 | `works.title` 参与检索，结果聚合到项目 |
| 分类 | `projects.category` | 支持但与路由段不一致 | 统一映射表 |
| 年份 | `release_date` | 支持 | 改为 `event_date` 优先 |
| 图片说明 | `gallery_assets.title/caption` | 支持 | 保留，结果显示所属项目 |

硬规则：
1. 搜索只返回 `portal_visible && curation_status <> 'archived' && !is_container`。
2. 结果卡片显示"项目名 + 分类 + 日期"，不显示 `catalog_id`。
3. 分类筛选值与 `lib/category-meta.ts` 单一映射，不允许页面各自写死。

## 6. 迁移阶段（每步独立可回滚）

| 阶段 | 内容 | 变更类型 | 回滚 |
|---|---|---|---|
| **M0** | 导出 `projects`、`gallery_assets`、`profiles` 全表 JSON + 当前 schema | 只读 | — |
| **M1** | `projects` 加 `slug`/`event_date`/`source_published_at`/`location`/`publisher_brand`/`search_aliases`/`is_container`/`updated_at`；`gallery_assets` 加 `file_hash`/`source_post_id`；`profiles` 加 `slug`/`bio_i18n`/`role_label` | 加列，全部 nullable 或有默认值 | `drop column` |
| **M2** | 建 `works`、`project_people`；填 2 部剧 + 26 行人物关联 | 新表 + 回填 | `drop table` |
| **M3** | 分类约束扩容（按 D2 定案） | 约束替换 | 恢复旧约束（需先回滚 M4 的值） |
| **M4** | 数据回填：`event_date`、`source_url`、`is_container`、`work_id` | 数据 UPDATE，逐条 RETURNING | 用 M0 快照逐行还原 |
| **M5** | 前台切换：导航、首页、路由 301、搜索、详情 | 代码 | `git revert` |
| **M6** | 停用废弃表与字段（不删表） | 代码 | 恢复读取 |

顺序不可颠倒：**先加列 → 再填数 → 再切前台**。绝不允许先改前台再补数据。

## 7. 迁移前必须完成的三份核对

1. **行数核对**：`projects` 26、`gallery_assets` 330、`profiles` 2、`project_people` = 26×N、`works` = 2。
2. **关联核对**：`gallery_assets where project_id is null` 必须仍为 0。
3. **可见性核对**：公开项目数、公开图片数迁移前后一致（当前 26 / 330）。
