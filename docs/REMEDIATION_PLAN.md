## 0. 原则（来自你的约束，每批都适用）

1. 小批量、可验证、可回滚：每批一个主题、一个提交，批与批之间可以停。
2. 不重构、不换栈、不合表、不提前建批量采集工作台 UI。
3. 不擅自改生产数据 / R2 对象 / 管理员账号 / 认证配置 / 生产环境变量。
4. 「本地通过」不等于「生产通过」：每批验收区分本地证据与生产证据。注意两类生产证据的区别：**生产库只读探测**（anon key 直连 Supabase，本环境可达）与**线上 HTTP 验收**（访问 lmsy.space，本环境不可达，需换网络）。
5. 每批完成即更新 `docs/FULL_AUDIT_REPORT_2026-10-16.md` 对应条目状态（问题关闭才划掉，不预先划掉）。
6. 本地 `next start` 会直连生产 Supabase 做只读 SSR 查询（`.env.local` 指向生产项目）——这是既有事实，不是新增风险，但意味着本地页面验证的数据来源就是生产数据。
